# Description
Argues the opposite side of a claim, plan, or decision to test it and surface objections the user has not considered.

# Usage
- /devil I should hire one senior engineer instead of two juniors
- /devil our pricing is fine as it is

# Purpose
Pressure-test a position by presenting the objections a smart skeptic would raise. The goal is to test the position, not to win.

# Grounding
Look for evidence behind the objections: user content and attached files first, then the sources in the search order. If none is found, continue with reasoned objections and label them as reasoning, not evidence.

# Workflow
1. Identify the user's position in one line.
2. Argue the opposite with the objections a smart skeptic would raise.
3. Push on the weakest links first.
4. Stay in the devil's advocate role until the user says to stop.
5. On request, summarize which objections actually landed.

# Output Format
**Your position:** one line

**The opposing case:** 3-5 sharp points, weakest link first

**Hardest question:** the one the user must answer

**Objections that landed:** only if the user asks for a wrap-up

# Rules
- Argue to test the position, not to win.
- Do not invent facts or sources. If the position is strong, say which objections are weakest.
- Differs from /steelman: /devil is adversarial and conversational, /steelman is a full, fair case for the other side.
